# AI Lab Phase 6 — ограниченный worker и наблюдаемое выполнение

Фаза 6 добавляет операторскую точку запуска для offline LightGBM-экспериментов.
Она не активирует модели и не имеет доступа к RuntimeSettings, gateway или ордерам.

## Запуск

После создания run и плана вызов:

```http
POST /api/ai-lab/runs/{run_id}/worker/lgbm
X-API-Key: ...
Content-Type: application/json

{"max_steps": 1}
```

Worker:

- выполняет не больше 10 шагов за один запрос;
- по умолчанию выполняет один шаг;
- сначала атомарно claim-ит шаг, затем коммитит claim до долгой операции;
- сохраняет каждый результат и ошибку в AI Lab;
- возвращает `step_id`, `config_id`, действие, статус и `result_id`;
- при частичной ошибке возвращает уже завершённые шаги и не скрывает причину.

Повторный вызов продолжает очередь с первого оставшегося `PENDING` шага. Параллельные worker-запросы используют `FOR UPDATE SKIP LOCKED`, поэтому один шаг не выполняется дважды.

## Безопасность

Ограничение `max_steps <= 10` является предохранителем от бесконечного автономного цикла.
Фаза выполняет только зарегистрированные offline LightGBM-действия:

- `TRAIN_MODEL`;
- `RUN_OOT_BACKTEST`;
- `RUN_POLYMARKET_OOT`.

Переход в SHADOW, запрос активации и изменение боевых настроек остаются отдельными операциями. После завершения очереди оператор вызывает `/evaluate`, затем проверяет отчёт и только после SHADOW принимает решение об активации.
